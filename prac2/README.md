# Практическая работа №2. Зависимости пакетов Ubuntu

Я сделала программу, которая показывает, какие пакеты нужны выбранному
пакету Ubuntu. Она находит и прямые зависимости, и зависимости этих
пакетов. Результат сохраняется в двух файлах, `.puml` и `.svg`.
Стрелка `A → B` на картинке означает, что пакет `A` зависит от `B`.

## Как запустить

Понадобятся Python 3, Java и файл `plantuml.jar`. Его нужно положить рядом
с `config.json`. Если установлена Java 8, на [странице PlantUML](https://plantuml.com/en/download)
есть отдельная сборка для неё. Собирать проект и ставить библиотеки через
`pip` не нужно.

В PyCharm можно открыть `src/main.py` и нажать Run. Из папки `prac2`
программа запускается командой `py -3 src/main.py` или через `run.bat`.

## Что можно поменять в config.json

- `package_name` — пакет, с которого начинается поиск.
- `repository` — ссылка на индекс `Packages.xz` или путь к тестовому файлу.
- `test_mode` — `true`, если нужен тестовый файл, и `false`, если нужен индекс Ubuntu.
- `version` — точная версия выбранного пакета из индекса. В тестовом файле версий нет.
- `output_file` — имя картинки, например `graph.svg`. Рядом появится `graph.puml`.
- `filter` — часть имени, по которой исключаются пакеты. Если здесь `""`, фильтр выключен.

Путь к тестовому файлу считается от папки с `config.json`.

## Что делают функции

- `main()` читает и проверяет настройки, а затем запускает построение графа.
- `check_repository()` проверяет адрес индекса или наличие тестового файла.
- `load_repository()` читает тестовый JSON или скачивает и разбирает индекс Ubuntu.
- `dependency_names()` берёт имена пакетов из полей `Depends` и `Pre-Depends`.
- `build_graph()` выбирает начальный пакет и запускает обход.
- `bfs()` проходит по графу по уровням, применяет фильтр и запоминает связи.
- `plantuml_text()` делает из пакетов и связей текст диаграммы.
- `save_graph()` записывает `.puml` и запускает PlantUML, чтобы получить SVG.

Для начального пакета проверяется версия. Остальные пакеты в графе записаны
по именам. Если в индексе стоит `A | B`, на схеме появятся обе стрелки.
Каждый пакет обходится один раз, поэтому стрелку, которая замыкает цикл,
можно показать и программа всё равно завершится.

## Как проверить

В исходных настройках включён тестовый режим. Если запустить программу,
она прочитает `tests/test_repo.json` и создаст `graph.svg`. Должно быть
четыре вершины и пять стрелок, в том числе `D → A`, которая замыкает цикл.

Если поставить `"filter": "B"` и запустить ещё раз, останутся три стрелки:
`A → C`, `C → D` и `D → A`. После проверки можно вернуть пустой фильтр.

## Примеры с пакетами Ubuntu

Для примеров ниже нужно поставить `"test_mode": false`, оставить фильтр
пустым и указать в `repository` ссылку на индекс Ubuntu 24.04 для amd64:

https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.xz

## Сравнение с apt

Для сравнения взяла `curl`. В PowerShell можно выполнить
`wsl.exe -d Ubuntu -- apt-cache dotty curl`. Команда выведет текст графа
в формате DOT. В обоих графах от `curl` идут стрелки к `libc6`,
`libcurl4t64` и `zlib1g`. Дальше есть различия. Например, в выводе APT
есть стрелка `libc6 → libc-gconv-modules-extra`, а в моей схеме её нет.

В WSL стоит Ubuntu 26.04, а в программе я использовала индекс Ubuntu 24.04.
Записи о пакетах в этих выпусках могут отличаться. Ещё APT рисует стрелки
для конфликтов между пакетами, а моя программа читает только поля
`Depends` и `Pre-Depends`.
